# KN-018 — ORION agent-spawn reliability observed 2026-07-05: 3 of 10 spawns this session d

**fact:** ORION agent-spawn reliability observed 2026-07-05: 3 of 10 spawns this session died mid-work (2 hit session/context limits, 1 got a connection-closed error) while leaving partial-but-real work on disk. Recovery protocol used successfully: diff the dead agent's claimed file ownership against actual `git status`/working-tree state, then either (a) finish the remaining delta inline in the orchestrator when small, or (b) re-spawn a narrowly-scoped agent targeting only the unfinished files. Do not blindly re-spawn the same broad task — it duplicates already-completed work and wastes tokens. New death mode observed 2026-07-28: a builder finished its work correctly on disk but returned an EMPTY/truncated report ('leaving the build running in background') without closing out its own verification. The orchestrator confirmed the artifact directly on disk and accepted it as done. Protocol: on a truncated/empty report, ALWAYS verify disk state before re-spawning — re-spawning here would have duplicated already-completed work. Separately, 2 of 15 spawns this session died from session limits (INFRA_DEATH) leaving no work at all in one case and complete work in the other — per RFC, infra-death does not inflate or deflate model-tier signal, record it as such rather than as a model failure.

**context:** Affected phases: build:restyle-datos (sonnet, escalate), build:restyle-flujo (sonnet, escalate), build:ui-tokens (sonnet, escalate). All three left recoverable partial work; none required a full restart.
