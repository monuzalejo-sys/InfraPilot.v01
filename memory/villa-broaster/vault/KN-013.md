# KN-013 — PLAN DE EQUIPO EN DOS PIEZAS: la documentación táctica del proyecto bifurcada en

**fact:** PLAN DE EQUIPO EN DOS PIEZAS: la documentación táctica del proyecto bifurcada en una pieza VISUAL INTERACTIVA (mobil-first, Google Fonts, tablero E1-E7, stepper, tabs por rol, acordeones T-01..T-10, calendario 4 semanas, sección 'Para el programador', 3 repos con accesos) + cuatro planes FORMALES A4 (PDF, 11-16 páginas cada uno según especialidad). (A) docs/plan-equipo.html = FRAGMENTO interactivo HTML5 (sin <html>/<head>/<body>, abre directo en navegador y es publicable como Artifact). Construcción: 126 KB, Google Fonts Bricolage Grotesque + Instrument Sans + Caveat (huecos), tablero visual E1-E7 + stepper de flujo + stepper de Caja, tabs para Desarrollador Senior / Diseñador Landing / Diseñadora / Dueño, acordeones detalle T-01..T-10 (cada uno con asignado/duración/bloqueadores/definición de hecho), calendario semanal 4 semanas, profunda sección 'Para el programador' (invariantes, verificación), listado de 3 repos con permisos. LECCIONES: (1) msedge --headless --screenshot en Windows RECORTA el viewport a mínimo de escritorio — para medir móvil usar emulación CDP (ORION/tools/edge-cdp.mjs en vez de captura headless) o el PNG se lee con artefactos; (2) builders pueden dejar archivos espurios por variables sin expandir ($name en shell = archivo literal 'docs/planes$name.pdf') — revisar 'git status' antes del commit; (3) auditar GÉNERO gramatical del destinatario en documentos personalizados (builder escribió femenino al diseñador de landing, requirió 1 corrección inline) — la regla: plan-{rol}.html/pdf va a PERSONAS, nombres cuentan; (4) NO hay renderizador PDF interno — verificar estructura PDF + captura del HTML fuente (KN-005 permanente). (B) docs/planes/plan-{desarrollador-senior, disenador-landing, disenadora, dueno}.{html,pdf} = planes formales A4 (16/11/11/12 páginas respectivamente, generados con Edge headless --headless + CDP para PDF en vuelo). Contenido fiel a tareas/ (T-01..T-10) + PLAN-EQUIPO. Cada PDF contiene: cabecera con nombre/rol/fecha, talón desglosado por etapa (qué hace en cada E1-E7, criterios de hecho), mapa de bloqueadores, contacto del senior para revisión. Proceso de generación: renderizar HTML → captura Edge CDP con viewports móvil (390x800 emulado en vez de --screenshot de escritorio que recorta) → generar PDF con puppeteer o Edge command-line. CALIBRACIÓN DE BUILDERS: build:visual con Opus (estándar Orama: alto pulido visual) MEJOR para la pieza interactiva que es el destino de PLAN-EQUIPO (128K artesanal); build:page con Sonnet OK para 4 planes PDF sobrios (templados, sin capricho visual).
