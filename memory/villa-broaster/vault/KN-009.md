# KN-009 — PROMOS SIN DESCUENTO FALSO: el servidor congela precios del catálogo al crear la

**fact:** PROMOS SIN DESCUENTO FALSO: el servidor congela precios del catálogo al crear la orden, así que un 'antes/ahora' en la UI de promos haría que el carrito prometa menos de lo que confirma la orden — las promos venden CURADURÍA, no rebajas inventadas. Dos modalidades en villa-app/lib/promos.ts (PROTOTIPO ESTÁTICO): 'para pedir' (agrega el combo completo al carrito) y 'solo en el local' (cupón troquelado CSS que revela código VB-* para mostrar en mostrador, NO viaja en el pedido). Al productizar: mover promos a dominio/almacén de broaster-app con sincronización periódica a villa-app (data/promos.json); mantener la semántica: promos venden experiencia y curaduría del negocio, no fantasías de descuento.

**context:** Insight de 2026-08-15 al implementar villa-app: evita la mentira del 'antes/ahora' que crea fricción checkout cuando la orden confirma otro precio. Regla general: si la UI promete un número, el servidor debe poder honrar exactamente ese número.
